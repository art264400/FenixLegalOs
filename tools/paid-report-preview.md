# Проверка страницы после оплаты

Из корня проекта запустите:

```powershell
python tools/preview-paid-report.py
```

Откройте <http://127.0.0.1:8783/preview>. Для остановки нажмите Ctrl+C в терминале.

Стенд использует настоящие HTML, CSS и JavaScript из `wwwroot`, а API возвращает
тестовую оплаченную диагностику. Приложение .NET запускать не нужно. Рабочая база,
учётные записи, оплата и LLM не используются. Отдельный адрес хранит своё состояние
браузера. Одновременно проверяйте один сценарий в одной вкладке.

- **Ждать до команды**: подготовка продолжается до нажатия «Завершить подготовку
  PDF» или «Вернуть ошибку». После двух минут появляется сообщение о долгом ожидании.
- **Готовность через 2 минуты**: выдача PDF автоматически разрешается через 120 секунд.
- **PDF готов сразу**: проверка состояния готового файла и кнопки скачивания.
- **Ошибка подготовки**: проверка сообщения об ошибке. Для проверки восстановления
  нажмите «Ждать следующую попытку», затем «Повторить подготовку» внутри приложения,
  затем «Завершить подготовку PDF» на панели стенда.

После выбора сценария нажмите **Начать заново**. Каждый запуск создаёт новую тестовую
диагностику и очищает её кэш в iframe. «Показать блок PDF» прокручивает страницу к
индикатору; переключатель ширины показывает мобильную вёрстку.

При скачивании используется существующий пример `scenario_medium.pdf`; он не
генерируется заново и не связан с условными оценками на странице. Если файла нет,
передайте путь к другому тестовому PDF:

```powershell
python tools/preview-paid-report.py --pdf "C:\path\to\test-report.pdf" --port 8783
```

Это проверка интерфейса и обработки ответов API. Настоящий платёж, проверку прав
доступа, сохранение в БД и генерацию PDF нужно проверять отдельно в приложении.
